# Workspace UI review — 24 October 2026

## Scope and structure

Reviewed dashboard routes, shared UI components, route styles, form feedback and the document/signature UI. The root layout supplies ToastProvider; AppFrame fixes the workspace to the viewport; PageContainer controls page spacing; Card, Header, Button and Modal supply shared presentation. Domain managers and workspaces handle data and actions.

## Findings and changes

| Finding | Change |
| --- | --- |
| Route CSS can override shared compact card/table spacing | Added explicit compact rules for Invoice, AP and Repayments |
| Wide tables can stretch their containing panel | Card/content containers have min-width zero; table wrappers scroll horizontally and vertically with sticky headings |
| Large result sets consume the whole page | Table regions are limited to 60dvh / 560px; the surrounding page remains independently scrollable |
| Shared Modal used an ARIA section without native focus containment | Switched to native dialog with Escape, focus containment, backdrop handling and internal scrolling |
| A shared dialog width rule overrode each form's intended maximum width | Removed that rule; the Users form was verified at 512px inside a 1280px viewport |
| Many action results appeared only inline | Added useFeedbackToast for Ledger, Repayments, contracts, category management, credit search, AP, borrower and lender feedback |
| Notifications can sit below native modal windows | Kept notifications in the browser top layer and observe dialog opening/closing to move their portal host |
| Multiple notifications can exceed screen height | Limited the toast stack to viewport height with internal scrolling |
| Notifications needed clear status cues | Added success/error/warning borders and restrained glow; messages remain readable without color |
| Backup initial loading triggered the React effect lint rule | Deferred the initial load with a cancellable microtask; manual reload remains available |

## Verification

- ESLint: `npx eslint app components --quiet` passed after the changes.
- Browser at 1280×720: reviewed Dashboard, Users, Borrowers, Lenders, Contracts, Ledger, Repayments, AP, AR, Accounting, Masterdata, Backups, Credit Bureau, Category, Postcode, Trade Payables, New Payable and Logs. The measured document width was 1280px; no measured Card exceeded the viewport width.
- Users Modal: native dialog opened, close control received focus, measured width 512px, height 569px; closed without changing data.
- Final TypeScript check: `npx tsc --noEmit` passed.
- No real financial entries, signatures, account permissions or user records were created or changed to test presentation.

## Follow-up recommendations

1. Gradually replace broad color-class selectors and repeated route CSS with explicit component tokens. The light theme currently overrides older dark rules; consolidate these to reduce future regressions.
2. Split large one-line manager components into form, toolbar, table and row-action components when those domains are next changed.
3. Use a shared table wrapper in future pages instead of adding new independent overflow rules. Large datasets should retain server-side pagination.
4. Perform a dedicated mobile, keyboard and contrast review with representative long names, empty states and dense data. This pass measured desktop layout and a representative Modal; it is not a complete accessibility certification.

No dedicated Company route/component was found. Shared table and Card constraints apply to existing workspace pages; a future Company screen should use the same shared components.
